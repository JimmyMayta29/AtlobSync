## APIs ya implementadas exitosamente:

1. **Registrar Preliminar** - POST sin body
2. **Exclusión Definitiva** - POST con query parameters  
3. **Tipo de Cambio Masivo** - POST con JSON array en body

## Headers estándar para SUNAT:
- Content-Type: application/x-www-form-urlencoded (mayoría)
- Content-Type: application/json (cuando hay body JSON)
- Accept: application/json
- Authorization: Bearer {token}

## Patrones de URL de SUNAT:
- Base: https://api-sire.sunat.gob.pe/v1/contribuyente/migeigv/
- Siempre incluyen perTributario (formato YYYYMM)
- Algunos usan query parameters adicionales

## Lo que necesito:

Cuando te pase la documentación de una nueva API de SUNAT, necesito que:

1. **Analices la documentación** (URL, parámetros, headers, body, método HTTP)
2. **Crees el código completo** siguiendo el patrón establecido:
   - Route registration
   - Controller con validaciones
   - Service con petición HTTP
3. **Incluyas ejemplo para Postman** con URL, headers y body si aplica
4. **Mantengas simplicidad** - código funcional sin sobre-ingeniería

## Notas importantes:
- Los errores 422 de SUNAT son normales al probar (datos no reales)
- El error 401 indica token expirado/inválido
- perTributario formato: YYYYMM (ej: 202402)
- Siempre validar parámetros obligatorios
- Usar fmt.Errorf para errores descriptivos
